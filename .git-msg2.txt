fix: 滚动滚不动的真正根因 —— 手势层把命中测试截断了

前两轮都修错了地方：问题不在正文控件，而在它上面那层手势。

Compose 的命中测试碰到一个没有声明「与兄弟共享」的指针输入节点时会直接
截断，画在它下面的兄弟节点根本不进入命中路径。源码依据
NodeCoordinator.PointerInputSource.shareWithSiblings：
  if (child.outerCoordinator.shouldSharePointerInputWithSiblings()) {
      hitTestResult.acceptHits(); return true
  }
  return false
而 Modifier.pointerInput 建出来的节点，该属性默认就是 false。

旧布局是 Box { Column(verticalScroll); Box(fillMaxSize().pointerInput{}) } ——
滚动容器在下面，一个事件都收不到。所以「只要不消费事件滚动就能继续」
从根上就是错的，把 SelectionContainer 换成 BasicTextField 再换成普通 Text
当然也都没用。这也解释了更早的「长按毫无反应」。

改法：手势层挂在根节点自己（父）上，子树是它的孩子 —— 父子不互相截断，
Main 阶段冒泡、子节点先处理，子节点消费过的手势父层不再处理。

为此把手势逻辑抽成 internal Modifier.readerPageGestures（ReaderGestures.kt），
并把 Compose UI 测试接到 JVM 侧，新增 ReaderPageGesturesTest（5 条，
真实注入触摸事件）：
  - 父节点手势层不会挡住子树滚动（swipeUp 后 scrollState.value > 0）
  - 兄弟层会让滚动彻底失效（scrollState.value 必须为 0，钉住框架规则）
  - 子树没人消费时点击仍被收到
  - 子树消费过的手势不再被当成点击
  - 横滑触发热区回调

同时修用户报的第二件事：滚动模式没有底部地脚（页码/时间/电量）。
地脚原先只画在分页视图里，滚动模式是单段结构。现在两种模式都是
「内容 weight(1f) + 独立地脚」，页码按滚动位置折算；电量广播的注册
提到阅读页最外层，两种模式共用（之前写在分页视图内部，滚动模式
即使有地脚也拿不到电量）。

测试：17 个文件 144 条用例，0 失败，零编译警告。
